# Current YOLO open verifier

The current-format open verifier accepts a deliberately narrow observed market-order transaction: one Pyth Lazer `UpdatePrice`, one SDK 0.6.0 `OpenPosition`, and bounded compute-budget instructions. It pins the observed upgradeable YOLO and Pyth ProgramData account hashes and slots. It permits the observed service signer or the live Config keeper, verifies the canonical signed BTC/ZEC Pyth feed against the current unexpired on-chain trusted ECDSA signer, and checks the exact market, price PDA, intent and account bindings. It simulates the original unsigned message and blockhash, then checks the position, price, collateral, token-account authority and lamport changes. The verifier repeats its checks after owner signing and immediately before transmission. RPC errors, changed deployment pins, unsafe token authorities and unsupported layouts fail closed.

The open is a market order. Its simulated entry is indicative and can change before execution; no entry-price limit is asserted. A newer program-owned oracle is accepted only when the market, feed, freshness and monotonic timestamp match and the simulated position entry equals that oracle. A failed transaction can incur a network fee; the verifier caps the quoted network fee at 0.01 SOL. The user also pays the verified position rent on a successful open.

This is an experimental known subset, not a source verification of the deployed YOLO or Pyth binaries. Both programs are upgradeable: off-chain hash checks detect observed changes but cannot atomically prevent an upgrade after verification. Simulation does not guarantee a later fill, execution price or account state. RPC providers can lag or rate-limit, and shared vault activity between prestate and simulation can cause a safe refusal. No live funded transaction has been tested by this verifier. **Current-format close is unavailable in this client**, because the claim identity and queued payout recipient are not established. A separate portal may offer controls, but this client does not verify or guarantee them. The earlier legacy verifier is unchanged.

`@noble/curves` 1.9.7 and `@noble/hashes` 1.8.0 are exact direct SDK dependencies used for secp256k1 recovery and Keccak. Both packages use the MIT license. Their public APIs are documented at https://github.com/paulmillr/noble-curves/tree/1.9.7 and https://github.com/paulmillr/noble-hashes/tree/1.8.0 . The package advisory requested a dependency reviewer, but that tool was unavailable in this session; independent dependency and security review remains required before merging or funded use.

The 2026-11-16 `npm audit --audit-level=moderate` exited 1 and reported four moderate transitive findings through `@solana/web3.js` → `jayson` → `stream-json`/`uuid`; the proposed automatic fix replaces web3.js with a breaking major version. Independent scoped review observed web3's browser JSON-RPC client using fetch and ordinary JSON parsing rather than the affected stream-json utility path, and UUID v4 without a supplied buffer rather than the advisory's v3/v5/v6 buffer cases. This is a reachability assessment of the reviewed paths, not a guarantee about every dependency path or a finding-free audit. The explicitly pinned noble dependencies did not produce audit findings.
